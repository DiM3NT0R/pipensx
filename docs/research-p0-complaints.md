### 2.2 Корневые технические причины
Главная причина массовости проблемы: **версия 1.6.2 (тег `7018d4f`) была собрана и выпущена ДО комплекса критических фиксов конца сентября**. На текущий момент репозиторий опережает релиз 1.6.2 на 28 коммитов (`1.6.2-28-g68cae89`). Все пользователи из чата используют старый билд 1.6.2, содержащий следующие дефекты:

1. **Deadlock / Ratchet-эффект EMA скорости (баг F1, закрыт в `e653bf2`):**
   - В 1.6.2 при открытии/закрытии шлюза установки (`package_coordinator.hpp`) вызывался `torrent_set_rate_freeze`.
   - При каждом выходе из троттлинга первый секундный замер скорости брал полупустой пайплайн и занижал `dl_rate_bps` на ~30%.
   - За 5–15 минут активной загрузки скорость экспоненциально деградировала до 0–3 байт/с. Загрузка полностью останавливалась, создавая у пользователя впечатление намертво зависшей консоли.

2. **CPU Fault и паника Atmosphere `0xFFE` / `std::abort` (Issue #86, закрыт в `4a59aba`):**
   - На крупных раздачах при большом числе пиров сетевой сервис Switch BSD выбрасывал ошибку `ENOBUFS` (исчерпание разделяемого пула буферов сокетов).
   - В 1.6.2 код `net.c` трактовал `ENOBUFS` как фатальный разрыв и немедленно закрывал пиров, вызывая шторм переподключений («handshake-then-close storm»).
   - Функция `piece_mgr_got_block` при транзиторном OOM буфера возвращала статус `1` (блок получен), из-за чего отменялись параллельные запросы, повреждался head-piece, и происходил фатальный `std::abort` через системный загрузчик HOS.

3. **ANR-сталл UI-потока (баг F2, закрыт в `9a5189c`):**
   - При интенсивном вводе-выводе и распаковке блоков NSZ на Switch фоновые воркеры и главный UI-цикл конкурировали за мьютексы менеджера задач, что блокировало обработку кадров Borealis на время более 10 секунд.

## 3. P0-2: Краш консоли при установке в память NAND

### 3.1 Контекст обращений
- **Kiru** (@Kiru45676, 21.09.2026, личный диалог и чат):
  - При установке Rayman Legends (2.98 ГБ) и Doki Doki Literature Club Plus (1.10 ГБ) в память консоли (NAND) происходит моментальный краш и перезагрузка HOS.
  - При установке тех же игр на microSD-карту процесс завершается успешно.
  - В памяти консоли (EmuNAND) свободно около 10 ГБ.

### 3.2 Технический анализ
1. **Разделение целевых хранилищ:**
   - В `src/install/install_backend_switch.cpp`:
     ```cpp
     NcmStorageId ncmStorageId(InstallStorageTarget target) {
         return target == InstallStorageTarget::Nand ? NcmStorageId_BuiltInUser
                                                     : NcmStorageId_SdCard;
     }
     ```
   - При этом временный каталог `TempRoot` жестко зашит на SD-карту:
     ```cpp
     constexpr const char* TempRoot = "sdmc:/switch/pipensx/install-temp";
     ```
   - Запись самого плейсхолдера контента идёт через системный сервис NCM в `NcmStorageId_BuiltInUser`.

2. **Уязвимость EmuNAND к нехватке блоков:**
   - Большинство пользователей кастомных прошивок создают EmuNAND на скрытом или файловом разделе SD-карты фиксированного размера (обычно 29–30 ГБ), где после установки системы свободно всего 10–12 ГБ.
   - В процессе стриминговой установки NSZ требуется память под:
     - Placeholder NCM (полный размер распакованного NCA);
     - Промежуточные буферы декомпрессии;
     - Системный резерв HOS (User Partition Threshold).
   - Если свободное место в `NcmStorageId_BuiltInUser` опускается ниже системного порога безопасности (Safe Margin ~500 МБ), вызов `ncmContentStorageSetPlaceHolderSize` или `ncmContentStorageWritePlaceHolder` завершается фатальным системным результатом (Result 0x205 / 0x805).
   - В релизе 1.6.2 отсутствовал отлов таких системных сбоев: процесс падал с паникой ядра Horizon, уводя консоль в аварийную перезагрузку.

3. **Отсутствие безопасного чекпоинта:**
   - До коммита `d4dcf84` (F5) первый чекпоинт журнала установки создавался только на рубеже 32 МиБ (`kJournalFirstIntervalBytes`). При краше на первых мегабайтах NCM-плейсхолдер оставался «подвешенным», повреждая реестр контента EmuNAND.

## 4. P0-3: Ошибочное определение базовой игры как DLC («Dispatch»)

### 4.1 Контекст обращений
- **Сергей Исаев** (@isaev_x, 07–08.10.2026, личный диалог, Telegram ID `110624023`):
  - Пользователь скачал через pipensx 1.6.2 игру **Dispatch Nintendo Switch 2 Edition** (Title ID `01008BA02525A000`).
  - Результат: на домашнем экране Switch отображается плитка игры с пунктирной рамкой (плейсхолдер DLC без базы). При нажатии — ошибка Horizon: *«Для игры требуется наличие этой программы»*.
  - Декодированный QR-лог `report-D89C.log` подтвердил успешную установку апдейта и DLC, но полное отсутствие установки базового пакета v0.

### 4.2 Корневая причина (Root Cause)
В `src/app/game_update_install.cpp` функция умного выбора файлов `selectSmartInstallFiles` классифицирует файлы раздачи на базу, обновление (Update) и DLC:

```cpp
// ИСХОДНЫЙ КОД (в версии 1.6.2):
bool isUpdateFile(const std::string& path) {
    std::string lower = path;
    std::transform(lower.begin(), lower.end(), lower.begin(),
                   [](unsigned char c) { return std::tolower(c); });
    if (lower.find("update") != std::string::npos ||
        lower.find("patch") != std::string::npos ||
        lower.find("upd") != std::string::npos)
        return true;
    ...
}
```

**Механизм сбоя:**
1. Имя файла базовой игры в раздаче: `Dispatch [01008BA02525A000][v0].nsp`.
2. Название игры **«Dispatch»** содержит в себе подстроку **`"patch"`**!
3. `lower.find("patch")` вернул совпадение. Функция `isUpdateFile` вернула **`true`** для базовой игры!
4. Алгоритм посчитал базовый файл `[v0]` файлом обновления.
5. Так как в раздаче присутствовал реальный патч `Dispatch [01008BA02525A800][v589824].nsp`, алгоритм умной установки сравнил их версии и посчитал `v0` устаревшим дубликатом апдейта, выставив ему статус `FileAction::Skip`.
6. Установщик установил патч `v589824` и DLC `v0`, а базовый пакет `v0` пропустил.
7. Horizon OS зарегистрировала патч и DLC, но не нашла базовой программы.

Аналогичная уязвимость была выявлена для:
- Подстроки `"upd"` (ложные срабатывания на тайтлы вроде *Cuphead*);
- Подстроки `"mod"` в `isLikelyModPackage` (ложные срабатывания на *Modern Combat*).

### 4.3 Решение
Исправлено и закоммичено в `78b5c19`: в `src/app/nx_file_types.hpp` и `src/app/game_update_install.cpp` реализованы строгие проверки:
1. Если имя файла содержит тег версии `[v0]` (`fileVersionTag(path, tag) && tag == 0`), файл **гарантированно не является апдейтом** (`return false`).
2. Поиск ключевых слов `"update"`, `"patch"`, `"upd"`, `"mod"` заменён на `containsDelimitedWord` (проверка границ слов, исключающая вхождение внутрь слова).
3. Добавлены регрессионные тесты в `tests/test_update_file_select.cpp`:
   - `testGameTitleContainingPatchWordNotTreatedAsUpdate()`
   - `testGameTitleContainingModWordNotTreatedAsMod()`

## 5. P0-4: Зависание в статусе «Скачано» («Downloaded»)

### 5.1 Контекст обращений
- **Nik** (@no_heart7, 10–11.10.2026): *«nfs зависла на статусе загрузки, и не устанавливает игру... в загрузках висит, а в основном меню игры нет, будто скачал - но не устанавливает ее почему то»*.
- **Ilia** (@calabaha, 30.09.2026): *«А что можно сделать, если скачался FC27, а установка не началась? Так и висит в статусе "Скачано"»*.
- **Чак** (@TET_Echter_Tee, 30.09.2026): *«Загружено И Не Могу Больше Нихуя Сделать»*.

### 5.2 Технический анализ
В архитектуре pipensx сосуществуют несколько несовместимых режимов:
1. **Коллизия типов контента:**
   - `StreamInstall` работает **исключительно** с контейнерами PFS0 (`.nsp`, `.nsz`).
   - Если пользователь выбирает раздачу порта (NFS, Half-Life 2, GTA), внутри которой находятся архивы (`.7z`, `.zip`, `.rar`) или исполняемые файлы `.nro`, менеджер загрузок переводит задачу в режим `DownloadOnly` или `PortInstall`.
   - В режиме `DownloadOnly` файлы успешно выкачиваются в каталог `sdmc:/switch/pipensx/downloads/`, после чего задача переходит в терминальный статус `Completed` («Скачано»).
   - Установка в NCM не происходит, тайл на Home Screen не создаётся. В интерфейсе отсутствует кнопка ручной установки для таких файлов.

2. **Проблема FAT32-сплита при дебрид-загрузках (из лога `pipensx (4).log`):**
   ```text
   [9916913] [storage] split '.../switch.7z' into 2 parts
   [9919837] [diagnostic] error=Unable to save download resume state: File exists
   [9919839] [debrid] fetch ended rc=23 (sink-refused)
   ```
   Если загружаемый не-NSP архив превышает лимит FAT32 в 4 ГБ, модуль хранилища разбивает его на части, но ошибка в сохранении резюма приводит к отказу приемника данных (`sink-refused`). Загрузка останавливается, а при повторном запуске циклически падает.

3. **RAR-архивы:**
   - Раздачи с трекеров, упакованные в RAR (баг F11), отлучаются модулем `package_stream.cpp:1184` («not a PFS0») и не могут быть установлены автоматически.

### Этап 3. Разрешение проблемы зависания «Скачано» (P0-4)
1. **Явный статус в UI:**
   - Если задача завершена в режиме `DownloadOnly`, статус должен отображаться не как «Скачано», а как:
     *«Файлы сохранены на SD-карту (/switch/pipensx/downloads)»*.
2. **Подсказка для портов:**
   - Для раздач с NRO и архивами показывать модальное окно:
     *«Это не стандартная игра Switch, а порт/архив. Файлы сохранены в папку загрузок. Для запуска распакуйте их в корень карты памяти или используйте DBI»*.
3. **Исправление FAT32 Resume State (`File exists`):**
   - Устранить конфликт перезаписи метаданных разбитого файла при возобновлении Debrid-загрузок.
